# Fracs — поиск владельцев + тариф PRO 2700₽ + раздел «Обучение»

Файлы лежат в `fracs-pro/` с теми же путями, что в репозитории. Перенесите поверх
рабочей копии (с заменой) и закоммитьте. Эти версии содержат и более ранние правки
(security + фичи: логотип, владельцы, колонки, ссылки) — используйте их как актуальные.

## 1. Починил поиск владельцев (было 0 из 5)

Причина «не найдено» — в `owners.py` сопоставление было слишком строгим: требовалось
`names_match(бренд ↔ юридическое лицо)`, что почти никогда не выполняется, а запасной
вариант «взять первый результат» был **внутри** ветки `names_match` и потому недостижим.
Плюс селекторы rusprofile были написаны наугад (автор патча предупреждал, что не проверял).

Что сделано в `desktop/parser_2gis/owners.py`:
- **Ранжирование всех пунктов** списка по совпадению (legal-name 3 балла, бренд 2,
  город +1, адрес +1) и выбор лучшего; **при отсутствии сигнала — первый результат**
  rusprofile (запрос строится из `name_ex.legal_name`, когда он есть, так что первый
  результат — та самая организация). Это убирает 0-находок.
- **Распознавание единственного совпадения**: если поиск сразу открыл карточку —
  разбираем её (`state:'card'`), без перехода по списку.
- **Широкие селекторы**: ссылки ловятся по регулярному `/\/(id|ip)\/\d+/` по всему
  `a[href]`, текст берётся из ближайшего контейнера (несколько классов + `li/article`).
- **Cloudflare/капча**: детектим «Just a moment / Checking your browser / капч» по
  title+body; в скрытом режиме — `OwnersCaptcha` с подсказкой снять «Скрытый браузер»;
  в видимом ждём ручного прохода до 3 мин. Окно ожидания увеличено до 30 с (Cloudflare
  очищается несколько секунд).
- `parse_card`: добавлены варианты ролей (Глава, Командир …), ИП ищется и в h1, и в тексте.

**Важно:** rusprofile отдаёт 403 даже браузерному UA (Cloudflare), поэтому селекторы
проверить из песочницы нельзя — программа ходит реальным Chrome (pychrome), который
проходит JS-челлендж. Прогоните на 5–10 записях; если список не находится — поправьте
`_JS_SEARCH` под актуальную вёрстку rusprofile (и `_JS_CARD` для карточки).

## 2. Тариф PRO 2700₽ + раздел «Обучение»

### Тарифы (`server/config.ts`)
`Plan` получил поле `features?: string[]`. Тарифы:
| id | title | цена | дни | features |
|----|-------|------|-----|----------|
| month | 1 месяц | 1800 | 30 | base |
| quarter | 3 месяца | 4500 | 90 | base |
| **pro** | **PRO 1 месяц** | **2700** | 30 | **base, owners, training** |

`ALL_FEATURES` — объединение всех кодов (админу выдаётся целиком).

### Хранение тарифа на пользователе (`server/db.ts` + `supabase/schema.sql`)
- `User.planId`, колонка `users.plan_id` (+ идемпотентный `alter table … add column if not exists`).
- `extendSubscription(userId, days, planId?)` теперь сохраняет тариф. Оплата (`payments.ts`)
  передаёт `plan.id`; бот `/grant` — необязательный 3-й аргумент.
- `getActiveFeatures(user)`: админ → все; подписчик с тарифом → его `features`; без
  тарифа → `['base']`.

### Раздел «Обучение» (контент — через админку в боте)
- Хранение: `app_settings` ключ `'training'` (JSON-массив уроков), как тарифы; in-memory
  + файл `data/training.json` фолбэк. Функции `getTraining/saveTraining/addLesson/updateLesson/deleteLesson`
  (`server/db.ts`). Урок: `{id, title, body, createdAt, order}`. `update/delete` — по id
  или префиксу (админ видит короткие id).
- **Бот-админка** (`server/bot.ts`): новые команды
  `/training`, `/addlesson <Заголовок>\n\n<Текст>`, `/setlesson <id> <Заголовок>\n\n<Текст>`,
  `/dellesson <id>`; `/grant … [тариф]` теперь принимает тариф. `/admin` показывает help.
- **API**: `POST /api/app/training` (для программы: ключ лицензии, гейт по `features.training`)
  в `server/appRoutes.ts`; `GET /api/training` (для кабинета, requireAuth + гейт) в
  `server/routes.ts`; `/me` отдаёт `features`; `/config` уже несёт `features` в планах.

### Программа (desktop)
- `license.py`: `check()` ловит `features` из `/api/app/verify` и хранит в кэше/файле
  (оффлайн-режим сохраняет последние features). Добавлен `app_fetch(path, payload)` —
  POST к `/api/app/*` с ключом лицензии.
- `web/server.py`: `/api/owners` теперь требует фичу `owners` (402 `feature_required`
  для базового тарифа); новый `GET /api/training` проксирует к `/api/app/training`
  через `app_fetch`, гейт по `features.training`.
- `index.html`: кнопка «Владельцы» и чекбокс «искать владельцев после парсинга» скрыты
  по умолчанию; самодостаточный блок читает `/api/license` → `features`, показывает их
  для `owners` и добавляет раздел «🎓 Обучение» (грузит `/api/training`, рендерит уроки)
  для `training`. Проверка каждые 60 с и при любом 402.

### Кабинет (`src/cabinet/`)
- `types.ts`: `Plan.features?`, `Me.features?`.
- `PlansModal.tsx`: для тарифа PRO рисует список «Поиск владельцев» / «Раздел Обучение».

## 3. Миграция БД (для существующих Supabase)
`supabase/schema.sql` уже содержит идемпотентный `alter table public.users add column
if not exists plan_id text;` — выполните файл в SQL Editor Supabase (повторный запуск
безопасен). Старым пользователям без `plan_id` соответствует `['base']`; чтобы открыть
им владельцев/обучение — `/grant <id> <дней> pro` в боте.

- `node --check tg.js` — OK.
- `index.html`: все маркеры правок на месте, NUL-разделители сохранены (2 шт.).

## 5. Как пользоваться
1. Залейте файлы, выполните `schema.sql` в Supabase.
2. В боте: `/grant <ваш_tg_id> 30 pro` (или купить PRO в кабинете — оплата передаст `plan.id`).
3. В программе: введите ключ лицензии из кабинета — «Владельцы» и «Обучение» появятся.
4. Наполнение обучения: в боте `/addlesson Заголовок` + пустая строка + текст урока.
   Список: `/training`, правка: `/setlesson <id> …`, удаление: `/dellesson <id>`.
